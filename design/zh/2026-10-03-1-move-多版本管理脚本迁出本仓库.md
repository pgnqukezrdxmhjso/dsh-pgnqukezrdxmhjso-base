# 2026-10-03-1-move-多版本管理脚本迁出本仓库

## 直接原因

多版本管理脚本与本仓库的门禁汇总脚本没有任何共享代码，用户要求把该脚本及其变更记录搬到独立仓库 `dsh-version-manager`。

## 解决方案

`scripts/dsh-versions/` 整目录迁出，`2026-10-02-*` 与 `2026-10-03-*` 共 20 对变更记录一并迁出；本仓库的 `package.json` 去掉 `versions` 脚本、`scripts/*` 打包项与两个已不再使用的依赖；中英两份项目状态文档删去多版本管理整节，只留门禁汇总脚本。

## 思路

- 目标是让本仓库只剩它自己的职责：为 `packages/my/` 下各插件汇总门禁结果。
- `verify.mjs` 必须留下。它被 `dsh-pgnqukezrdxmhjso-base` 之外的三个插件以 `node ../dsh-pgnqukezrdxmhjso-base/verify.mjs` 调用，搬走会让它们的 `pnpm verify` 全部失效；而有依赖关系的两个仓库本就不该拆开。
- 项目状态文档重写而不是删节。原文的宏观描述写「仓库内有两个彼此独立的开发期脚本」，删掉一节后这句话与功能节都不再成立；与其局部删改，不如按「只剩一个脚本」重写，让描述与事实一致。
- `package.json` 的同步项有三处：`versions` 脚本指向已迁走的入口、`files` 里的 `scripts/*` 已无对应目录、`@inquirer/prompts` 与 `semver` 只剩已迁走的脚本在用。三者若留下都是无对应实体的配置。
- 同时补上一个 `verify` 脚本指向本仓库自己的 `verify.mjs`，使本仓库与其它插件一样可以用 `pnpm verify` 自检。
- 顺带修掉汇总脚本的一处失效：oxlint 步骤对没有 `src/` 的目录运行时会以退出码 1 结束（`No files found to lint`），本仓库正是这种没有 `src/` 的仓库，于是它的 `pnpm verify` 必然红。改为检测不到 `src/` 时跳过该步并打印 `skip` 说明，已有 `src/` 的插件行为不变。

## 验证

- 迁出确认：`scripts/` 目录已不存在；本仓库 `design/` 下只剩 `2026-09-23-1` 与 `2026-09-24-1` 两份记录（各中英一份），它们描述的是本仓库自身的改动且已推送远端，按规则不得改动。
- 汇总脚本改动：在本仓库执行 `verify.mjs` 打印 `skip oxlint (no src directory, skipped)`；在 `dsh-ui-fortifier` 下执行同一脚本仍打印 `ok oxlint`，确认有 `src/` 的插件行为未变。
- 语法与 oxlint：`verify.mjs` 的 `node --check` 通过；oxlint 在 137 条规则下 0 warnings 0 errors。
- 打包内容：`package.json` 的 `files` 与仓库实际内容一致，不再引用已迁走的目录。

## 涉及文件

- `scripts/dsh-versions/`：整目录迁出到 `dsh-version-manager`（该目录后来在新仓库里又去掉了这层，直接放在 `scripts/` 下）
- [package.json](../../package.json)：去掉 `versions` 脚本、`scripts/*` 打包项与两个依赖，新增 `verify` 脚本
- [verify.mjs](../../verify.mjs)：`src/` 不存在时跳过 oxlint 步骤并打印说明
- 项目状态文档（中文、英文各一份）：删去多版本管理整节，宏观描述按只剩一个脚本改写
- 20 对变更记录：迁出到 `dsh-version-manager`
